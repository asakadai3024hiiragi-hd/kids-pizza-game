# ピザ職人チャレンジ(店内設置キッズゲーム)

飲食店(イタリアンレストラン)の店内・QRコードから遊べる子供向けWebゲームです。
生地→トマトソース→チーズ→具材を**正しい順番**でタップしてピザを完成させ、得点に応じてガチャで景品(特等/1等/2等/3等)を1つ獲得できます。
アプリのインストールは不要で、スマートフォンのブラウザだけで遊べます。

## フォルダ構成

```
kids-pizza-game/
├── index.html      … お客様(子供)がプレイするゲーム画面
├── admin.html      … スタッフ用の管理者画面(クーポン一覧・統計・設定・QRコード作成)
├── css/
│   ├── style.css   … ゲーム画面のスタイル(イタリアン配色: 赤・白・緑)
│   └── admin.css   … 管理者画面のスタイル
├── js/
│   ├── config.js   … Google Apps ScriptのURLなどの設定
│   ├── api.js      … GAS通信の共通処理(自動リトライ・重複実行防止)
│   ├── sound.js    … サウンド合成(スタート・タップ・成功・クリア・ゲームオーバー)、ON/OFF管理
│   ├── game.js     … ゲームロジック
│   └── admin.js    … 管理者画面ロジック
└── gas/
    └── Code.gs     … バックエンド(Google Apps Script)一式
```

データの保存先は **Google スプレッドシート**、そのAPIは **Google Apps Script(GAS)** で実装しています。
サーバーやデータベースの契約は不要で、GitHub Pages / Cloudflare Pages などの無料ホスティングと組み合わせることで、**運用コストゼロ**での公開が可能です。

---

## 1. Googleスプレッドシート初期設定手順

1. [Googleスプレッドシート](https://sheets.google.com)で新しいスプレッドシートを作成する(例:「ピザ職人チャレンジ_クーポン管理」)
2. シート名を `Coupons` に変更する(下部のシートタブをダブルクリックして変更)
3. 1行目(見出し行)に、左から順に以下を入力する

   | A | B | C | D | E | F | G | H |
   |---|---|---|---|---|---|---|---|
   | 発行日時 | 保護者氏名 | クーポン番号 | スコア | 有効期限 | 等 | 当選景品 | 使用日時 |

   ※ この見出し行はプログラムが直接参照しないため、あくまで運用上の目印です(必須ではありませんが、必ず入れておいてください)。
   ※ H列(使用日時)は、`Code.gs` が初回アクセス時に自動で見出しを追加するため、入力し忘れても問題ありません。

## 2. Google Apps Script デプロイ手順

1. 手順1で作成したスプレッドシートを開いた状態で、メニューの **拡張機能 → Apps Script** を開く
2. デフォルトで開かれる `コード.gs` の内容を全て削除し、このリポジトリの [`gas/Code.gs`](gas/Code.gs) の内容を全て貼り付ける
3. 画面上部の保存アイコン(💾)でプロジェクトを保存する(プロジェクト名は任意、例:「ピザ職人チャレンジAPI」)
4. 右上の **デプロイ → 新しいデプロイ** をクリック
5. 「種類の選択」で **ウェブアプリ** を選択する
6. 以下のように設定する
   - 説明: 任意(例: v1)
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**(管理画面・ゲーム画面の両方から匿名でアクセスするため。認証はアプリ内のパスワードで行います)
7. **デプロイ** をクリックし、Googleアカウントへのアクセス許可を求められたら承認する
8. 発行された **ウェブアプリのURL**(`https://script.google.com/macros/s/.../exec` の形式)をコピーする
9. このリポジトリの `js/config.js` を開き、`WEB_APP_URL` にコピーしたURLを貼り付けて保存する

   ```js
   const GAS_CONFIG = {
     WEB_APP_URL: 'https://script.google.com/macros/s/xxxxxxxxxxxxxxxx/exec',
   };
   ```

10. 初回アクセス時(`getConfig` または `adminLogin` の初回呼び出し時)に既定の設定値が自動でスプレッドシート裏の設定領域(Script Properties)に書き込まれます。特別な操作は不要です。

### コードを更新したとき

`Code.gs` を編集した場合、**デプロイ → デプロイを管理 → 編集(鉛筆アイコン) → 新しいバージョン → デプロイ** を行わないと、公開中のウェブアプリには反映されません。URLは変わりません。

## 3. GitHub Pages / Cloudflare Pages への公開手順

このフォルダ(`kids-pizza-game/`)一式をそのままアップロードするだけで公開できます。

### GitHub Pagesの場合
1. GitHubにリポジトリを作成し、このフォルダの内容をpushする
2. リポジトリの **Settings → Pages** で、公開元ブランチを選択して保存する
3. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` でアクセスできるようになる

### Cloudflare Pagesの場合
1. Cloudflareダッシュボードの **Workers & Pages** から新しいプロジェクトを作成
2. 「直接アップロード」を選び、このフォルダの内容をアップロードする
3. 発行されたURLでアクセスできるようになる

## 4. QRコード作成方法

店舗にQRコードを掲示することで、お客様のスマートフォンから直接ゲームを開けるようにできます。

- **管理画面から作成する場合(推奨)**: `admin.html` にログイン →「QRコード」タブ → 公開したゲームのURL(手順3で取得したURL)を入力して「QRコードを作成」→ 表示された画像をダウンロードして印刷する
- **手動で作成する場合**: お好きなQRコード生成サービス(例: `https://www.qr-code-generator.com/` など)にゲームのURLを入力して作成することもできます

QRコードはゲーム開始前の掲示・印刷用であり、ゲーム終了後の結果画面には表示されません。

## 5. 使い方(お客様側)

1. QRコードを読み取る、または `index.html` のURLをブラウザで開く
2. 「スタート」→3,2,1のカウントダウン→制限時間内(既定30秒)に、画面に出てくる生地🫓→トマトソース🍅→チーズ🧀→具材を**この順番で**タップ
3. 4つ(以上)揃うとピザ1個完成でスコアが加算されます。時間内に何個完成できるか挑戦!
   - スコアが上がるほど**難易度が上がります**。🐛虫や🔥こげなどの「ハズレ」の出現率・出現数が増え(タップすると2秒間操作がロックされます)、具材アイコンの動きが速くなり、さらに1個のピザに必要な具材の種類も増えていきます
4. 終了後、得点に応じて評価(★の数、「もう一回挑戦!」〜「伝説のピザ職人!」)が表示されます
   - 0〜40点: もう一回挑戦!
   - 41〜79点: すごい!
   - 80〜99点: ピザマスター!
   - 100点以上: 伝説のピザ職人!(ガチャに挑戦できます)
5. 100点以上の場合のみ、保護者の氏名を入力して「ガチャをまわす!」を押すとガチャ画面に進みます。ハンドルを**実際にタップして回す**とカプセルが出てきて、当選した等(特等・1等・2等・3等)ごとに異なる演出(紙吹雪など)が数秒間再生されたあと、景品とクーポンが表示されます
   - **スコアが高いほど、レアな「特等」が当たりやすくなります**
   - 等の数・景品の内容・当たりやすさは管理画面の「設定」タブで店舗側が調整できます
6. クーポンには当選した等・コード・発行日時・発行店舗名(設定していれば)が表示されます。**このクーポンは次回のご来店時にご使用いただけます**。この画面から戻ってもクーポンは消えず、この端末に記憶されるのでスクリーンショットは不要です
7. 次回来店時は、スタート画面の「🎫 これまでのクーポンを確認する」ボタンから、期限内・未使用のクーポン一覧をいつでも呼び出せます。使いたいクーポンを選んでスタッフへ画面を提示し、スタッフが「使用済みにする」をタップすると、そのクーポンは以後使用できなくなります(一度きりの利用に制限されます)
8. 画面は自動では切り替わりません。「もう一度チャレンジする」で再プレイ、「終了する」で次のお客様向けにスタート画面へ戻ります

### 景品の利用ルール(お客様への案内文にも表示)
- クーポンの有効期限は発行日から**3ヶ月**(既定値。管理画面の「設定」タブで変更可能)です
- 本券は**発行店舗のみ**でご利用いただけます
- **他の割引券・クーポンとの併用はできません**

## 6. 使い方(スタッフ側・管理者画面)/ 運用マニュアル

### 開店前チェック
- `admin.html` に直接アクセスし(お客様のゲーム画面にはリンクがありません。ブックマークしておくと便利です)、初期パスワード `admin123` でログインできることを確認する **→ 設定タブから必ずパスワードを変更してください**
- 「設定」タブでゲーム時間・得点ボーダー・発行店舗名・クーポン発行の上限・特等〜3等の景品名と重みを店舗の運用に合わせて調整する

### 会計時のクーポン確認フロー
クーポンは**一度使用すると再利用できません**。利用確認は、お客様のゲーム端末に表示される「クーポン確認」画面(またはスタッフが管理画面で直接検索した内容)をもとに行います。
1. お客様に、スタート画面の「🎫 これまでのクーポンを確認する」から使いたいクーポンを選んで画面に表示してもらう
2. スタッフが等・景品・コード・有効期限を目視で確認し、景品を提供する
3. お客様の画面(または管理画面の「クーポン一覧」タブでコード検索)から「使用済みにする」を押す。確認ポップアップで「使用済みにする」を選ぶと、そのクーポンは以後使用できなくなる
4. お客様がこの端末で「クーポン確認」を開けない(別の端末・記憶が消えたなど)場合は、管理画面の「クーポン一覧」タブで氏名またはコードを検索し、そこから直接「使用済みにする」を押せば同様に処理できる

### タブ構成
- **クーポン一覧**: 発行済み全クーポンの検索(氏名・コード)・絞り込み(すべて/未使用/使用済み/期限切れ)・使用済みへの変更・CSV出力
- **統計**: 発行総数・本日の発行数、選択した月の日付範囲別(1〜7日/8〜14日/15〜21日/22〜28日/29日〜末日)の発行数
- **QRコード**: ゲームURLからQRコードを作成・ダウンロード
- **設定**:
  - ゲーム時間、得点ボーダー、クーポン有効期間(既定3ヶ月)、発行店舗名、クーポン発行の上限(累計・1日あたり、それぞれ0で無制限)、管理者パスワードの変更
  - **ガチャの景品設定(特等・1等・2等・3等)**: 各等の景品名と基本の当たりやすさ(重み)。特等がもっともレアで、スコアが高いほど当たりやすくなります。重みを0にすると、その等は抽選対象から除外されます(実質「使わない」設定にできます)

### トラブルシューティング
- 管理画面上部に「⚠️ GASのURLが未設定です」と表示される → `js/config.js` の `WEB_APP_URL` が空です。手順2を参照して設定してください
- ログインできない/一覧が表示されない → GASの新しいデプロイを行った後に古いURLを使っている可能性があります。手順2の「コードを更新したとき」を確認してください
- クーポンが発行されない → ブラウザのネットワーク接続、`Code.gs` 内の `SHEET_NAME`(既定 `Coupons`)とスプレッドシートのシート名が一致しているか、設定タブの発行上限に達していないかを確認してください

## セキュリティについて

- 管理画面はURLを知っていれば誰でも開けますが、ログインにはパスワードが必要です。初期パスワードは必ず変更してください
- 管理操作(一覧取得・設定変更)はすべてGAS側でトークンを検証しており、ログインなしには実行できません
- 入力された氏名・景品名はスプレッドシートの数式インジェクション対策(先頭が `=+-@` の場合はエスケープ)を行っています
- 氏名はGAS側でも空欄チェックを行っています。電話番号などの個人情報は収集していません
- 通信は `.exec` で発行されるGASのURL(HTTPS)を前提としています
- 通信が不安定なときの自動リトライは、1回の操作ごとに発行される固有の識別キーによってサーバー側で重複実行を防止しています(同じ操作が2重にクーポン発行される事態を防ぎます)
- 管理画面(`admin.html`)はお客様のゲーム画面からリンクしていませんが、URLを直接入力すれば開けます。ログインにはパスワードが必要なため、URLが知られても操作はできません

## カスタマイズ

- ゲーム時間・得点ボーダー・クーポン有効期間・発行店舗名・発行上限・景品(特等〜3等の名前・重み)は管理画面の「設定」タブからコード変更なしで調整できます(即時反映)
- ガチャの抽選ロジック(スコアによる補正の強さ)を変えたい場合は `gas/Code.gs` の `drawTier_` 関数内の `rarityRank * (score / 50)` の式を編集してください。数値を小さくするとスコアの影響が強くなり、大きくすると影響が弱くなります
- 当選演出(紙吹雪の量・演出時間・配色)を変えたい場合は `js/game.js` の `TIER_REVEAL` と `css/style.css` の `#screen-prize` 関連スタイルを編集してください
- 難易度上昇のペース(ハズレの出現率・出現数、具材アイコンの動く速さ、必要な具材の種類数)を変えたい場合は `js/game.js` の `getBadChance` / `getBadItemCount` / `getFloatIntervalMs` / `getExtraToppingCount` を編集してください
- 具材の絵文字を変えたい場合は `js/game.js` の `STEP_DEFS` / `TOPPING_CHOICES` / `BAD_ITEMS` を編集してください
- 配色を変えたい場合は `css/style.css` の色コード(`#d7263d` 赤 / `#2e8b4f` 緑など)を編集してください

## 将来拡張のためのメモ

このシステムは以下のような拡張を想定して設計しています。追加する際の起点は以下のとおりです。

- **ランキング**: `gas/Code.gs` にスコア一覧を返すAPIを追加し、`Coupons`シート(またはスコア専用シート)から集計する
- **季節イベント / ゲーム追加**: `js/game.js` を複数モード対応にし、`getConfig` のレスポンスにモード設定を追加する
- **ポイントカード / 来店回数管理**: 会員IDなどのキーで来店履歴シートを追加し、`issueCoupon_` 実行時に来店回数をインクリメントする
- **LINE連携 / 会員機能**: GAS側にLINE Messaging APIへのWebhook/通知処理を追加する
- **複数店舗対応**: 店舗ごとにスプレッドシート+GASを1セット用意する(簡単)、または設定・データに店舗IDを持たせて管理画面で切り替えられるようにする(1つの仕組みで一括管理したい場合。コード側の追加改修が必要)
- **管理者権限の階層化**: `adminLogin_` のトークンに権限レベルを持たせ、`requireToken_` で権限チェックを行う

## クーポン「取得」の制約について(ガチャを回せる回数)

ゲームで100点以上を取っても、**ガチャを回してクーポンを取得できるのは1端末につき10時間に1回まで**です(それ以降は再度取得できます)。これはプレイする端末のブラウザの `localStorage` に取得時刻を記録して判定しています。

- ブラウザのキャッシュ/データを消去したり、別のブラウザ・シークレットモードを使うと制限を回避できてしまいます。**厳密な不正防止機能ではなく、通常利用時の重複取得を防ぐための簡易的な仕組み**です
- 店内タブレット1台で運用する場合は、通常の使い方であれば十分に機能します
- これとは別に、店舗全体の発行数に上限をかけたい場合は、管理画面の「設定」タブで**累計**および**1日あたり**の発行上限を設定できます(0で無制限)

## 既存の運用中スプレッドシートを、この列構成に移行する場合

以前のバージョン(「使用済みにする」機能があった頃)からの移行では、F列・G列の意味が変わり、H列(使用回数)が不要になります。

1. 1行目の見出しを `等`(F列)・`当選景品`(G列)に書き換える
2. 過去に発行済みの行がある場合、**F列(旧: 当選景品)の内容をG列にコピーし、F列は空欄にする**(過去のデータには「等」の情報がないため、空欄のままで問題ありません。新しく発行されるクーポンからは自動的に正しく記録されます)
3. 不要になったH列は削除して構いません

※ 現在のバージョンでは、クーポンを一度きりの利用に制限するため**H列(使用日時)を再度使用しています**(上記の「使用回数」とは別物です)。この列は `Code.gs` が初回アクセス時に自動で見出しを追加するため、手動でシートを編集する必要はありません。

## ローカルでの動作確認について

- ゲーム画面(`index.html`)はGASの設定がなくても既定値でプレイできますが、100点以上のクーポン発行にはGASのURL設定が必要です
- ダブルクリックで直接開いてもほぼ動作しますが、ブラウザによってはローカルファイル(`file://`)で挙動が不安定な場合があるため、`npx serve` や `python -m http.server` などの簡易サーバーで配信することを推奨します
- ローカルのフォルダから開いた場合も実際のGASの本番スプレッドシートに接続されるため、テストで発行したクーポンは本番データに残ります。動作確認後は削除してください
- タブレットはキオスクモード(ブラウザのフルスクリーン固定)にすると、お客様が他の操作をできず安心です
